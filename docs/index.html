Architecture Overview

GeoLang is a modular geospatial platform with 23 product repositories. Twenty-one are Rust services, libraries, or command-line tools. GeoLang is Python, and ViewTopia is TypeScript and React. The deployable platform is orchestrated through Docker Compose.

Design Principles

  • Independent repositories: Each component keeps its own releases, CI, tests, and dependency policy
  • Edition 2024: All crates use Rust edition 2024
  • AGPL-3.0-or-later: Consistent licensing across all repositories
  • Contained unsafe Rust: Unsafe code is limited to native library, plugin, GPU, and mobile FFI boundaries
  • Error propagation: thiserror for library errors, anyhow for CLI

Infrastructure & CI/CD

GitHub Actions Workflows

Every product repository has a CI workflow. Most Rust repositories also publish release binaries and rustdoc. ViewTopia adds full-stack Docker, panel sweep, load, and platform end-to-end workflows.

ci.yml

Formatting, linting, and tests for each repository. Rust repositories also run cargo-deny and coverage where their workflow defines them.

release.yml

Present in repositories that publish binaries. Tagged releases build the targets defined by that repository and publish GitHub release artifacts.

docs.yml

Present in repositories that publish rustdoc. Documentation is deployed to https://geolang.github.io/{repo}/.

Dependency Management

  • Renovate: Weekly updates for Cargo, npm, and GitHub Actions dependencies, grouped non-major and held three days after release. Each repo's renovate.json extends the shared policy in renovate-config
  • cargo-deny: License allowlist, ban duplicate detection, source verification
  • Allowed licenses: MIT, Apache-2.0, Apache-2.0 WITH LLVM-exception, BSD-2/3-Clause, ISC, Unicode-3.0, Unicode-DFS-2016, Zlib, MPL-2.0, AGPL-3.0-or-later, OpenSSL, CC0-1.0, WTFPL, NCSA, BSL-1.0, CDLA-Permissive-2.0. ring is the one per-crate exception

Templates & Governance

  • CONTRIBUTING.md: Standard contribution workflow
  • CODE_OF_CONDUCT.md: Contributor Covenant v2.1
  • Issue templates: Bug reports and feature requests
  • PR template: Description, changes, testing checklist
  • CHANGELOG.md: Keep a Changelog format with semantic versioning

Development Guide

Prerequisites

# Rust toolchain (stable)
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
rustup component add clippy rustfmt llvm-tools-preview

# Tools
cargo install cargo-deny cargo-llvm-cov

# For server development, bring up the platform stack from viewtopia.
# scripts/platform-up.sh generates the shared JWT secret into .env.platform,
# fetches the OSM extract, and waits on every healthcheck.
cd viewtopia && ./scripts/platform-up.sh

Clone All Repos

#!/bin/bash
REPOS=(agora collecta fenestra fluvius geodukt geogit geokode geolang \
       geoplumb interiora itinera jung nubis panoptes projicio ptolemy \
       sibyl terrano terravista tiletopia topoi verne viewtopia)

for repo in "${REPOS[@]}"; do
  git clone git@github.com:GeoLang/${repo}.git ~/src/${repo}
done

Testing Strategy

Test Pyramid

  • Unit tests: In-module #[cfg(test)] blocks for internal logic
  • Integration tests: crates/{name}-core/tests/ for public API exercising
  • Benchmarks: crates/{name}-core/benches/ using Criterion (topoi, projicio, geokode)
  • Load tests: viewtopia/loadtest, k6 against the full stack, nightly. The k6 thresholds are the pass/fail
  • Platform end-to-end: 35 Playwright tests in viewtopia/tests/e2e run by playwright.platform.config.js against the composed stack, no stubs
  • Coverage: cargo llvm-cov with reports uploaded to Codecov in CI

Running Benchmarks

# Run all benchmarks for a crate
cargo bench -p topoi-core

# Run a specific benchmark
cargo bench -p projicio-core --bench projections

# Compare against baseline
cargo bench -p geokode-core -- --save-baseline main
# ... make changes ...
cargo bench -p geokode-core -- --baseline main

Coverage Report

# Generate HTML coverage report
cargo llvm-cov --all-features --workspace --html --open

# Generate LCOV for CI
cargo llvm-cov --all-features --workspace --lcov --output-path lcov.info

Security & Supply Chain

cargo-deny Configuration

Every Rust repository except sibyl includes a deny.toml that enforces:

  • License compliance: Only pre-approved FOSS licenses
  • Advisory database: RUSTSEC vulnerability checks (informational in CI)
  • Source verification: Only crates.io registry, no unknown git sources
  • Ban detection: Warns on duplicate crate versions in dependency tree

Security Practices

  • Unsafe Rust is kept at native library, plugin, GPU, and FFI boundaries
  • Input validation at all API boundaries
  • Parameterized queries for PostGIS (no SQL injection)
  • TLS: the hosted deployment serves HTTPS only at its CloudFront edge. The self-hosted Compose stack serves plain HTTP on port 8080 and expects your own TLS terminator in front
  • Secrets via environment variables, never hardcoded

Deployment

Release Process

  1. Update CHANGELOG.md under [Unreleased] → [x.y.z] - YYYY-MM-DD
  2. Bump version in workspace Cargo.toml
  3. Create and push a git tag: git tag -a v0.2.0 -m "Release v0.2.0" && git push --tags
  4. GitHub Actions builds binaries and creates a GitHub Release

Docker

# Build any server component
docker build -t geolang/ptolemy:latest -f Dockerfile .

# The whole platform, from the viewtopia checkout
cd viewtopia
./scripts/platform-up.sh              # or, with .env.platform already written:
docker compose --env-file .env.platform -f docker-compose.platform.yml up --build

Production Notes

  • Observability: Rust HTTP services use tracing and expose logs through their containers. Set RUST_LOG=info, or a service-specific filter such as geokode=debug, to control verbosity.
  • Rate Limiting: Handle at the reverse proxy level (nginx limit_req_zone, HAProxy, or cloud LB). Application-level rate limiting is not included because infrastructure-level rate limiting is more reliable, configurable, and avoids type-system complexity with axum's service traits.
  • Load Testing: viewtopia/loadtest exercises the composed platform with k6.
  • Health Checks: Services used by the composed platform expose health routes consumed by Docker Compose and the platform tests.
