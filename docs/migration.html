Migration Guide

Step-by-step instructions for migrating from existing GIS platforms to GeoLang.

Migrating from GeoServer

GeoServer is a Java-based OGC server. GeoLang replaces it with Fenestra (OGC gateway) + Ptolemy (feature store).

What maps to what

GeoServer ConceptGeoLang Equivalent
WorkspacePtolemy Dataset
Layer / FeatureTypePtolemy Branch (versioned layer)
DataStore (PostGIS)Ptolemy Storage (PostGIS-backed)
SLD StylesPtolemy Cartography / Fenestra Styles
WMS/WFS endpointsFenestra OGC API
GeoWebCache tilesTileTopia (3D Tiles + MVT)

Step-by-step migration

Export your data from GeoServer

# Option A: Export as GeoJSON via WFS
curl "http://geoserver:8080/wfs?service=WFS&version=2.0.0&request=GetFeature&typeNames=workspace:layer&outputFormat=application/json" > layer.geojson

# Option B: Export directly from PostGIS
ogr2ogr -f GeoJSON layer.geojson PG:"host=localhost dbname=geo" "schema.table"

# Option C: Export as GeoPackage (preserves schema better)
ogr2ogr -f GPKG export.gpkg PG:"host=localhost dbname=geo" "schema.table"

Start the GeoLang platform

# Clone repos and start Docker Compose
cd viewtopia
docker compose -f docker-compose.platform.yml up --build -d

Create a dataset and branch in Ptolemy

# Create dataset
ptolemy dataset create "buildings" --srid 4326 --geometry-type polygon --created-by admin

# Note the dataset ID from output, e.g. 019...
# Create a branch
ptolemy branch create --dataset <dataset-id> "main" --created-by admin

Import your data

# Import GeoJSON
ptolemy import --branch <branch-id> layer.geojson --author admin -m "Initial import from GeoServer"

# Import Shapefile
ptolemy import --branch <branch-id> layer.shp --author admin -m "Import shapefile"

# Import GeoPackage
ptolemy import --branch <branch-id> export.gpkg --author admin -m "Import from GeoPackage"

Configure Fenestra for OGC access

Use the dashboard at http://localhost:4000/dashboard/layers to add layers pointing to Ptolemy branches. Fenestra provides WMS, WFS, and WMTS endpoints compatible with QGIS, ArcGIS Pro, and other clients.

Migrating from ArcGIS Enterprise / Online

ArcGIS is a proprietary platform. GeoLang replaces it with an open-source stack:

ArcGIS ConceptGeoLang Equivalent
Feature ServicePtolemy (versioned features + REST API)
Map Service / TilesTileTopia (3D Tiles + MVT)
GeocoderGeokode
Network AnalysisItinera (routing + isochrones)
ArcGIS Online PortalViewTopia (web viewer + AI agent)
GeoprocessingGeodukt (ETL pipelines)
Scene Viewer (3D)ViewTopia CesiumJS globe
Field MapsCollecta (field data collection)
NavigatorTerraVista (mobile SDK)

Export from ArcGIS

# Using GDAL/OGR to export from ArcGIS Feature Service:
ogr2ogr -f GeoJSON buildings.geojson \
  "https://services.arcgis.com/ORG_ID/arcgis/rest/services/Buildings/FeatureServer/0/query?where=1%3D1&outFields=*&f=geojson"

# Or export from File Geodatabase:
ogr2ogr -f GeoJSON parcels.geojson input.gdb parcels

# Or as GeoPackage:
ogr2ogr -f GPKG export.gpkg input.gdb

Import into GeoLang

# Same as above — create dataset, branch, then import
ptolemy dataset create "parcels" --srid 4326 --geometry-type polygon --created-by admin
ptolemy branch create --dataset <id> "main" --created-by admin
ptolemy import --branch <id> parcels.geojson --author admin

Migrating from Mapbox

Mapbox is a SaaS mapping platform with per-request pricing. GeoLang gives you the same capabilities self-hosted:

Mapbox Tiling ServiceTileTopia
Mapbox GeocodingGeokode
Mapbox DirectionsItinera

Mapbox DatasetsPtolemy Datasets + Branches

Style migration

Mapbox GL styles are JSON objects. GeoLang's ViewTopia uses MapLibre GL which is 100% compatible with Mapbox GL styles. Simply:

  1. Export your style JSON from Mapbox Studio
  2. Replace mapbox:// tile URLs with your TileTopia URLs
  3. Remove the Mapbox access token requirement

Using QGIS with GeoLang

QGIS connects directly to GeoLang services:

  • WMS/WFS: Add Fenestra as an OGC connection → http://localhost:3003/wms
  • PostGIS: Connect directly to the Ptolemy database → localhost:5432
  • Vector Tiles: Add TileTopia as a Vector Tile source → http://localhost:3100/tiles/{z}/{x}/{y}.pbf
  • Geocoding: Use the QGIS geocoding plugin with Geokode → http://localhost:3001/search?q=...

API Access & Authentication

Generate an API key

# Create a key for programmatic access
ptolemy apikey create "ci-pipeline" --role editor --expires-days 90
# → ptk_019...  (save this!)

# Use it in API requests:
curl -H "X-API-Key: ptk_019..." http://localhost:3000/datasets

JWT Authentication

# Set the JWT secret:
export PTOLEMY_JWT_SECRET="your-secret-here"

# Tokens are generated via OIDC callback or manually:
# See ptolemy-api docs for OIDC configuration

Webhooks & Event Streaming

# Register a webhook for commit notifications:
curl -X POST http://localhost:3000/datasets/<id>/webhooks \
  -H "Content-Type: application/json" \
  -d '{"url": "https://your-app.com/hook", "events": ["commit"], "secret": "hmac-secret"}'

# Webhook payloads include HMAC signature in X-Ptolemy-Signature header
# Delivery has automatic retries with exponential backoff (1s, 2s, 4s)

Backup & Restore

# Backup (custom format — recommended for pg_restore)
ptolemy backup dump.backup --custom

# Backup (plain SQL)
ptolemy backup dump.sql

# Restore
ptolemy restore dump.backup --clean
