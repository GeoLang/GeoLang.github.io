Migration Guide

Step-by-step instructions for migrating from existing GIS platforms to GeoLang.

Migrating from GeoServer

GeoServer is a Java-based OGC server. GeoLang replaces it with Fenestra (OGC gateway) + Ptolemy (feature store).

What maps to what

GeoServer ConceptGeoLang Equivalent
WorkspacePtolemy Dataset
Layer / FeatureTypePtolemy Branch (versioned layer)
DataStore (PostGIS)Ptolemy Storage (PostGIS-backed)
SLD StylesPtolemy Cartography / Fenestra Styles
WMS/WFS endpointsFenestra OGC API
GeoWebCache tilesTileTopia (3D Tiles, terrain, PMTiles vector tiles)

Step-by-step migration

Export your data from GeoServer

# Option A: Export as GeoJSON via WFS
curl "http://geoserver:8080/wfs?service=WFS&version=2.0.0&request=GetFeature&typeNames=workspace:layer&outputFormat=application/json" > layer.geojson

# Option B: Export directly from PostGIS
ogr2ogr -f GeoJSON layer.geojson PG:"host=localhost dbname=geo" "schema.table"

# Option C: Export as GeoPackage (preserves schema better)
ogr2ogr -f GPKG export.gpkg PG:"host=localhost dbname=geo" "schema.table"

Start the GeoLang platform

# Clone the repos side by side, then bring the stack up from viewtopia.
# platform-up.sh writes the shared JWT secret into .env.platform, fetches
# the OSM extract, and waits on every healthcheck.
cd viewtopia
./scripts/platform-up.sh

Create a dataset and branch in Ptolemy

# Create dataset
ptolemy dataset create "buildings" --srid 4326 --geometry-type polygon --created-by admin

# Note the dataset ID from output, e.g. 019...
# Create a branch
ptolemy branch create --dataset <dataset-id> "main" --created-by admin

Import your data

# Import GeoJSON
ptolemy import --branch <branch-id> layer.geojson --author admin -m "Initial import from GeoServer"

# Import Shapefile
ptolemy import --branch <branch-id> layer.shp --author admin -m "Import shapefile"

# Import GeoPackage
ptolemy import --branch <branch-id> export.gpkg --author admin -m "Import from GeoPackage"

Serve the data over OGC

There is nothing to configure. Fenestra derives its layers from Ptolemy: a layer name is a Ptolemy dataset name, and the features come from that dataset's main branch, or its first branch when it has no main. It serves WMS 1.3.0, WFS 2.0.0, WMTS 1.0.0, WCS 2.0.1 and OGC API Features and Tiles, which QGIS, ArcGIS Pro and GDAL read unchanged. Set FENESTRA_PUBLIC_URL to the externally reachable base URL, path prefix included, or the capabilities documents will advertise the container's own bind address.

Export from ArcGIS with Verne

Verne reads KML, KMZ, Esri file geodatabases and hosted ArcGIS feature services, and before moving anything it reports item by item whether GeoLang holds it faithfully, approximates it, or has no home for it. The source is never written to. File geodatabases need the gdb feature and GDAL 3.8 or later. The KML and feature service paths are pure Rust.

# what is in it, and what would survive the move
verne inspect wells.gdb
verne inspect https://host/arcgis/rest/services/Wells/FeatureServer

# every feature service in a portal, URL first
verne services https://www.arcgis.com --owner your-org-account

# write the features, the semantics and the attachments out as a sidecar
# (a geodatabase extraction also writes a GeoPackage beside it)
verne extract wells.gdb --out ./wells-extract --operator you@example.com

# create what the sidecar describes in a running Ptolemy
export VERNE_PTOLEMY_TOKEN=<a bearer token that may write>
verne load ./wells-extract --ptolemy http://localhost:3000

A private feature service reads VERNE_ARCGIS_TOKEN, or mints its own from VERNE_ARCGIS_CLIENT_ID and VERNE_ARCGIS_CLIENT_SECRET.

Or export with GDAL

# From an ArcGIS Feature Service:
ogr2ogr -f GeoJSON buildings.geojson \
  "https://services.arcgis.com/ORG_ID/arcgis/rest/services/Buildings/FeatureServer/0/query?where=1%3D1&outFields=*&f=geojson"

# From a File Geodatabase:
ogr2ogr -f GeoJSON parcels.geojson input.gdb parcels

# Or as GeoPackage:
ogr2ogr -f GPKG export.gpkg input.gdb

Import into GeoLang

# Same as above — create dataset, branch, then import
ptolemy dataset create "parcels" --srid 4326 --geometry-type polygon --created-by admin
ptolemy branch create --dataset <id> "main" --created-by admin
ptolemy import --branch <id> parcels.geojson --author admin

Style migration

Mapbox GL styles are JSON objects. GeoLang's ViewTopia uses MapLibre GL which is 100% compatible with Mapbox GL styles. Simply:

  1. Export your style JSON from Mapbox Studio
  2. Replace mapbox:// tile URLs with your TileTopia URLs
  3. Remove the Mapbox access token requirement

Using QGIS with GeoLang

QGIS connects directly to GeoLang services:

  • WMS/WFS: Add Fenestra as an OGC connection → http://localhost:3003/wms
  • PostGIS: Connect directly to the Ptolemy database → localhost:5432
  • Vector Tiles: Add a TileTopia PMTiles source as a Vector Tile connection → http://localhost:3100/martin/{source}/{z}/{x}/{y}, with its TileJSON at http://localhost:3100/martin/{source}
  • Geocoding: Use the QGIS geocoding plugin with Geokode → http://localhost:3001/forward?q=..., with /reverse and /autocomplete beside it

API Access & Authentication

Generate an API key

# Create a key for programmatic access
ptolemy api-key create "ci-pipeline" --role editor --expires-days 90
# → ptk_019...  (save this!)

# Use it in API requests:
curl -H "Authorization: Bearer ptk_019..." http://localhost:3000/api/v1/datasets

JWT Authentication

# One HS256 secret signs {sub, exp, role} tokens for every service, so a
# user is one subject across the platform. Ptolemy reads it as:
export PTOLEMY_JWT_SECRET="32+ bytes, required to serve"

# The platform compose passes the same value as PLATFORM_JWT_SECRET to
# every other service. Tokens come from an OIDC callback
# (PTOLEMY_OIDC_ISSUER_URL and friends) or are minted directly.

Webhooks & Event Streaming

# Register a webhook for commit notifications:
# Instance admin only: a subscription sends dataset content to a URL.
curl -X POST http://localhost:3000/api/v1/datasets/<id>/webhooks \
  -H "Authorization: Bearer <admin token>" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://your-app.com/hook", "events": ["commit"], "secret": "hmac-secret"}'

# Webhook payloads include HMAC signature in X-Ptolemy-Signature header
# A failed attempt is retried with a doubling backoff, five attempts in all

Backup & Restore

# Backup (custom format — recommended for pg_restore)
ptolemy backup --custom dump.backup

# Backup (plain SQL)
ptolemy backup dump.sql

# Restore
ptolemy restore dump.backup --clean
